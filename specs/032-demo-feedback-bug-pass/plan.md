# Implementation Plan: Demo Feedback Bug Pass

**Branch**: `032-demo-feedback-bug-pass` | **Date**: 2026-08-15 | **Spec**: [spec.md](./spec.md)

## Summary

Turn the hosted-demo reports into one staged correctness and usability pass.
Extend immutable lap and transaction evidence into pure presentation models;
make tags, synergy, scaling categories, upgrades, settlement, and run records
explicit; add one context-preserving inventory overlay/full-window controller;
complete three deterministic economy items; tune only underperforming exclusive
item pools against reproducible balance gates; and replace prioritized primitive
chrome using the approved neutral control sheet. Existing garage, tiering,
settlement, race, and run authorities remain the only mutation paths.

## Technical Context

**Language/Version**: TypeScript 5.5, ECMAScript 2020  
**Primary Dependencies**: Phaser 3.80, Vite 5; no new runtime dependency  
**Storage**: Versioned in-memory run/build/history state; no backend or browser persistence added  
**Testing**: Vitest; strict test-first for simulation, settlement, economy, undo,
history, and balance; presentation-contract tests before Phaser integration  
**Target Platform**: Modern desktop/mobile web, existing 800×450 logical canvas  
**Project Type**: Single-project 2D browser game  
**Performance Goals**: Preserve 60 fps watched playback; stat/tag projection is
linear in the held catalog (maximum seven items); no per-frame catalog scans or
texture generation; inventory opens within one frame from retained state  
**Constraints**: Recorded evidence only during playback; identical stock vehicle
stats; no Nell nerf; no new cross-race scaling; no live race inventory; exact
context restoration; static GitHub Pages compatibility; approved sheet is
1672×941 and requires deterministic crop/nine-slice metadata  
**Scale/Scope**: 70 shipped items, four entrants, eight-car scored races, all
active-run non-playback scenes, three economy items, three prioritized UI surface
families, four independently testable workstreams

**Structure Decision**: Extend the existing single-project separation. Pure
simulation modules own item, economy, placement, history, and reversible-sale
state. Pure scene-presentation modules project those facts. Phaser scenes own
only drawing, focus, pointer/touch/keyboard routing, and context lifecycle.

## Delivery Order

1. Freeze baseline regressions for all reports and add catalog-wide scaling/tag
   classification plus deterministic balance harnesses.
2. Correct item rule text, Interchangeable Test Mounts, scaling evidence, and
   the three economy capabilities in pure simulation/content modules.
3. Extend settlement/history with third-place reputation, economy breakdowns,
   and exact scored-race W/L projection.
4. Add pure live-stat, tag inspection, tier-up, and transaction presentation
   models, then integrate watched race and Results surfaces.
5. Fix Supplier purchased/restock states and Reward Draft `SKIP REWARDS` while
   preserving existing authoritative acquisition commands.
6. Add the shared inventory session/controller, responsive overlay/full-window
   projection, sell target, and one-step Undo; integrate each eligible scene.
7. Run the reproducible pool audit, tune Evelyn/Lucien/Inez existing exclusive
   values/synergies only, and prove both parity bands without changing Nell or
   stock vehicle stats.
8. Define crop metadata from the approved transparent sheet, replace
   championship indicators, pre-race controls, and shared primary buttons in
   that order, preserving semantic focus states.
9. Run focused and full automated gates, deterministic replay/balance reruns,
   keyboard/touch/pointer coverage, and supported-viewport visual QA.

# Implementation Plan: World Championship Expansion

**Branch**: `029-championship-expansion` | **Date**: 2026-08-13 | **Spec**: [spec.md](./spec.md)

## Summary

Replace the short flat championship with a deterministic five-leg world tour:
four player-selected regions and a fixed Paris finale, totaling 40 stages and
20 races. Extend versioned run state with persistent destination offers,
regional schedules, Local/Championship race classification, seven season
rivals, standings, one-use Last Chance, and finale mode. Author 49 compact PvE
profiles whose legal builds feed the same setup/simulation/playback/result
pipeline as player ghosts. Recompose the hub as a world-map itinerary and bind
the seven approved regional backgrounds through presentation-only theme keys.

## Technical Context

**Language/Version**: TypeScript 5.5, ECMAScript 2020  
**Primary Dependencies**: Phaser 3.80, Vite 5; no new runtime dependency  
**Storage**: Versioned in-memory run/ghost records; no backend in this feature  
**Testing**: Vitest; test-first for scheduling, settlement, standings, opponent
generation, Last Chance, and all deterministic boundaries  
**Target Platform**: Modern desktop/mobile web, existing 800×450 logical canvas  
**Project Type**: Single-project 2D browser game  
**Performance Goals**: 60 fps playback; tour derivation linear in 40 stages;
49-profile content validation completes during test/build, not per frame  
**Constraints**: Eight-car fields; recorded opponents only; no hidden regional
physics/PvE pace modifiers; shared contest pipeline; max 16 laps; preserve dirty
feature 025/027/028 worktree changes  
**Scale/Scope**: 7 regions, 5 legs/run, 40 stages, 20 races, 49 local profiles,
7 persistent season rivals, 7 regional backgrounds, 1 hub redesign

**Structure Decision**: Extend the existing single-project architecture. Pure
simulation modules own every consequential rule; content modules contain
authored identities/tendencies; Phaser scenes render pure presentation models
and never calculate standings, settlement, offers, or opponent pace.

## Delivery Order

1. Add versioned region/leg/stage/race-kind types and the legacy-run guard.
2. Implement deterministic destination offers and the exact 40-stage schedule.
3. Add race-kind settlement, contract targeting, standings, tie-breaks, and
   Last Chance as pure tested state transitions.
4. Author and validate 49 profiles; derive legal Qualifier/Challenge snapshots
   through existing build, setup, track, and contest APIs.
5. Implement persistent season-rival evolution, normal finale, and an injected
   exact-track elite-record source with labeled deterministic fallbacks.
6. Wire run navigation so both race types share PreRace → Contest → Results and
   every transition records immutable evidence exactly once.
7. Build destination choice and the world-map itinerary/current-leg models.
8. Preload and bind the seven regional masters via presentation-only keys with a
   neutral fallback; verify that simulation does not import visual metadata.
9. Update all player copy, sponsor targeting, results/history, summary, and
   failure explanations to Local Race/Championship Race terminology.
10. Run focused tests, full `npm test`, lint, build, deterministic replay checks,
    and viewport/browser QA. Hand feature 030 the unchanged playback boundary.
